## 本地运行前端

仓库的 `web/` 目录现在有一个可运行的 React + Vite 前端，连接 Supabase 中的模拟数据。

1. 安装 Node.js（建议使用当前 LTS 版本）。
2. 在终端进入 `web/` 目录，安装依赖：`npm install`。
3. 复制 `web/.env.example` 为 `web/.env.local`，填入 Supabase 项目 URL 和 Publishable key。Vite 变量名以 `VITE_` 开头；不要把 `service_role` key 放进浏览器端。
4. 在 `web/` 目录运行 `npm run dev`，打开终端显示的本地地址。

第一次上课可以把这件事解释成三步：React 负责画页面，Supabase 保存共享数据，前端用项目 URL 和公开的 Publishable key 请求数据。

## 当前版本包含

详细思路见[产品改进方案](docs/04_产品改进方案.md)。

**老人模式**（默认打开，大字；底部三个按钮：今天 / 我的记录 / 问小安）
- 今天：小安主动提醒；用药打卡；点卡片直接填血压、睡眠和家属设置的其他项目；心情；"哪里不舒服"按钮
- 我的记录：最近 7 天，大字列表
- 和小安对话：说一段话也能记录，小安复述确认后才保存。读数不合常理先确认，超出范围给提示（血压偏高复测、血糖偏低先补糖等）
- 遇到加减药、诊断问题会拒绝并建议问医生；提到胸痛等急症提示拨打 120
- 拍照上传病历，标为"未核对"；可以记下想问医生的问题
- 支持语音输入和朗读回答（取决于浏览器）

**家属模式**（老人首页右上角进入，演示密码 1234）
- 日常总览：血压、其他记录项目和不舒服的情况；用药清单和今天的打卡；**每天要记的项目**；老人同意后才开启短信通知家人（演示版只预览，不发送）
- 复诊与病历：设置下次复诊日期；整理上次就诊以来的记录，可修改、打印、复制；查看、核对老人拍照上传的病历，录入病历文字

**记录项目可以扩展**：得什么病很难预先知道，所以每天记什么由家属或医生设置。睡眠、心情、哪里不舒服所有人都记；血压、血糖、体重、体温、血氧是预设项目；不在列表里的（比如尿量、腿围）可以自己加，并按医生的意见填提醒范围。血压存在 `daily_checkins`，其他项目每次一行存在 `measurements` 表（建表语句见 [supabase/migrations](supabase/migrations/20261027_measurements.sql)），加新项目不用改数据库。提醒范围只是示例，需要临床老师核对。

**演示版限制**：用药清单、记录项目设置、打卡、复诊日期、病历照片只保存在当前浏览器里；没有登录与角色权限。当前数据库是课堂演示配置，表格开放匿名读写；只能使用模拟资料。它可以作为可运行的课堂演示版，不能直接用于真实长辈资料或作为安全的医疗产品上线。

## GitHub Pages

推送到 `main` 后，`.github/workflows/deploy-pages.yml` 会自动构建并发布 `web/`。首次启用时，请在 GitHub 仓库 Settings → Pages 中将 Build and deployment 的 Source 设为 GitHub Actions。成功后网址为 `https://dylanmiao7.github.io/SyCare/`。

## 模拟数据

data文件夹只有三张数据表：12位老人、360条合并健康与关怀的每日记录、24条病历；`data/测试数据/` 中有三份对应不同老人的上传测试PDF。三张表用patient_id关联。

正式建表与模拟数据导入已在 Supabase 完成；`data/` 素材不是生产数据库迁移。

真实健康数据试用另行确认部署。模拟人数不是实际服务人数，模拟数据不能证明医疗效果。
