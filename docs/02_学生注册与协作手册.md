# 学生准备手册：GitHub + Supabase + DeepSeek

项目：SyCare，面向国内老人的中文健康记录与问答助手。

完成目标：拥有自己的开发账号，把导师的仓库克隆到电脑，提交一次小修改，准备好数据库与AI接口配置。开发页面将在课上建立；当前仓库主要是计划、说明和模拟数据，没有可直接启动的完整应用。

操作核对日期：2026-09-17。菜单可能更新，以官方页面为准。预计主动操作60—90分钟，计入20小时计划的环境准备阶段；验证和审核等待另计。

## 先认识三个平台

| 平台 | 项目中的作用 | 你要完成什么 |
|---|---|---|
| GitHub | 保存代码文档，与导师同步修改 | 注册、接受邀请、克隆 |
| Supabase | 登录、数据库、文件和后端函数 | 注册、加入同一个开发项目 |
| DeepSeek开放平台 | 提供AI回答能力 | 注册、创建API key、准备测试额度 |

准备可收邮件的邮箱、电脑和密码管理工具。安装GitHub Desktop与VS Code，选择Windows或macOS对应版本。注册、付款和身份验证由本人完成；未成年人的付费与账户安排和监护人、导师确认，遵守平台要求。

## 第一步：注册GitHub

1. 打开[注册页](https://github.com/signup)，按页面填写邮箱、密码、用户名并完成验证。
2. 选择适合长期使用的用户名并记下。免费个人账户即可开始。
3. 完成邮箱验证，按账户提示开启双重验证，恢复码存入私人密码管理工具。
4. 将 **GitHub用户名** 发给导师，便于添加协作者。不提供密码或恢复码。
5. 安装[GitHub Desktop](https://desktop.github.com/download/)，选择登录GitHub，使用自己的账户授权。
6. 安装[VS Code](https://code.visualstudio.com/download)，用于打开和编辑项目。

完成标志：浏览器和GitHub Desktop都登录了你自己的账户。

项目仓库：[dylanmiao7/SyCare](https://github.com/dylanmiao7/SyCare)。核对时为公开仓库，可阅读和克隆；写入仍需要导师邀请。公开仓库只存程序、文档和模拟数据。

官方参考：[创建GitHub账户](https://docs.github.com/en/account-and-profile/how-tos/account-management/creating-an-account-on-github)

## 第二步：接受邀请，把仓库克隆到本地

### 导师先做

打开SyCare仓库的 **Settings → Collaborators → Add people**，搜索学生用户名并邀请。学生在邮箱或GitHub通知中接受。不必另建SyCare仓库。[协作者说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository)

### 学生操作

1. 打开[SyCare仓库](https://github.com/dylanmiao7/SyCare)。
2. 点击绿色 **Code → Open with GitHub Desktop**。
3. 选择本地位置，例如 `Documents/GitHub/SyCare`，点击 **Clone**。
4. 如果没有唤起Desktop，在Desktop中选 **File → Clone repository → URL**，填 `https://github.com/dylanmiao7/SyCare.git`，选择保存位置。
5. 点击 **Fetch origin**。准备内容若尚未合并，在 **Current branch** 切到 `codex/china-mvp-plan-and-onboarding`；合并后回到 `main`，按导师通知为准。
6. 选择 **Repository → Open in Visual Studio Code**。若没有编辑器菜单，直接在VS Code选择“打开文件夹”，找到刚克隆的SyCare。

“拖到本地”对应的标准操作是 **Clone（克隆）**。克隆后可以把整个文件夹拖进编辑器；不要只下载ZIP，也不要重新建立同名仓库，这样才能保留同步关系。

完成标志：能打开 `README.md`、`docs/01_20小时开发流程.md` 和 `data/demo_cn/README.md`。若只有最初的README，先Fetch并检查分支。

当前准备材料没有前端脚手架，此时不要运行 `npm install` 或 `npm run dev`。导师建立应用并补充启动说明后，再安装依赖。命令不是注册环节的要求。

官方参考：[用GitHub Desktop克隆](https://docs.github.com/en/desktop/adding-and-cloning-repositories/cloning-a-repository-from-github-to-github-desktop)

## 第三步：注册Supabase并准备开发项目

1. 打开[Supabase Dashboard](https://supabase.com/dashboard)，按页面提供的邮箱或GitHub入口注册/登录，完成验证。
2. 先确认导师是否已有开发组织：**已有就接受邀请，不重复创建项目**。尚未建立时，可按后续步骤创建专用教学组织，再邀请导师。
3. 创建本项目专用组织，例如 `SyCare Learning`。选择当前可用的免费方案；若页面要求付费，先与导师确认，不在此步骤购买升级或附加服务。
4. 点击 **New project**，选组织，项目名填 `sycare-dev`；设置独立的数据库密码，保存到密码管理工具。它不是API key。
5. 模拟数据开发项目可选页面提供的Singapore区域，先由导师确认。它是境外区域，不表示适合存放国内真实健康资料。
6. 等待项目创建成功，打开 **Connect**，找到 **Project URL** 和 **Publishable key**。
7. 完整密钥设置在 **Settings → API Keys**。前端用 `sb_publishable_...`；不要把 `sb_secret_...` 或旧式 `service_role` 放入前端。
8. 如由你创建组织，在组织的Team/成员设置中邀请导师的Supabase注册邮箱，邮箱由导师提供。已有导师组织则由导师邀请你，按需要给Developer权限。

开发组织只放SyCare。控制台成员是开发人员，不是软件里的老人账号；老人登录与家属授权将在课上另建。

完成标志：你和导师能访问同一个项目，能找到Project URL和Publishable key。暂不手工建表、关闭RLS或公开文件桶；先在课上完成权限设置，再导入模拟数据。

免费方案的限制以当前页面为准。成员能否仅访问某个项目与套餐有关，不假定免费组织支持项目级授权；使用本项目专用组织能简化协作。

官方参考：[建立项目](https://supabase.com/docs/guides/getting-started/quickstarts/reactjs)；[API keys](https://supabase.com/docs/guides/getting-started/api-keys)；[成员管理](https://supabase.com/docs/guides/platform/access-control)；[可用区域](https://supabase.com/docs/guides/platform/regions)

## 第四步：注册DeepSeek开放平台

1. 打开[DeepSeek开放平台](https://platform.deepseek.com/)，按页面完成注册、登录和验证。
2. 确认进入的是API开放平台。普通聊天网页能提问，不等于本项目已经有API额度。
3. 从API keys入口创建项目专用key，名称可写 `sycare-dev`。入口也可从[首次调用文档](https://api-docs.deepseek.com/zh-cn/)进入。
4. 创建后立即把完整key存入私人密码管理工具，不贴进GitHub、聊天群、作业截图或共享文档。
5. 查看余额与用量。和导师或监护人确认小额测试预算，再按页面充值；不假设有免费额度或固定最低充值额。
6. 课上从后端做一次短文本测试，例如“请回复连接成功”，不发送个人信息。手册不会替你执行付费调用。

当前官方连接地址为 `https://api.deepseek.com`，初始模型配置使用 `deepseek-flash`。模型名与价格会更新，首次调用前再次核对官方文档，不照搬旧教程名称。

完成标志：能登录开放平台，项目key已安全保存，清楚测试额度来源。报错只分享去掉密钥和个人信息的内容。

### 把key放到后端

在Supabase项目进入 **Edge Functions → Secrets**（或函数密钥管理入口），保存下面三项。授课时老师可以协助填写，不用把key发到微信群。

| 名称 | 填写内容 |
|---|---|
| DEEPSEEK_API_KEY | 刚创建的完整API key，仅后端保存 |
| DEEPSEEK_BASE_URL | https://api.deepseek.com |
| DEEPSEEK_MODEL | deepseek-flash，调用前核对可用性 |

`.env.server.example`仅展示字段与占位内容，不自动上传Secrets，也不表示API已经连通。

官方参考：[DeepSeek首次调用](https://api-docs.deepseek.com/zh-cn/)；[Supabase函数Secrets](https://supabase.com/docs/guides/functions/secrets)

## 第五步：本地配置与第一次小修改

导师建立React/Vite前端后，将根目录 `.env.example` 复制为 `.env.local`，只填Supabase的Project URL和Publishable key。使用VS Code创建文件，避免误存成 `.env.local.txt`。

```text
VITE_SUPABASE_URL=https://你的项目编号.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=你的publishable_key
```

`VITE_`变量会进入前端。DeepSeek key、数据库密码和Supabase secret/service_role不能放进去。`.env.local`已被忽略，提交前仍检查Changes列表。

本地调试后端时按导师安排，将 `.env.server.example` 复制为 `.env.server.local`，也会被忽略。在线函数仍用控制台Secrets；前端配置不能替代它。

### 做一次协作练习

1. Desktop选中SyCare，先 **Fetch origin**。确认导师指定的起始分支，有更新时 **Pull origin**。
2. 用 **Branch → New branch** 从正确分支建立自己的分支，例如 `student/setup-check`。
3. 新建 `docs/student_setup_check.md`，只写GitHub用户名和三个平台的准备情况，不写密钥、密码或真实病历。
4. 在Desktop查看Changes，确认只包含要提交的文件。
5. Summary写 `docs: add student setup check`，点击 **Commit to 当前分支**。
6. 首次用 **Publish branch**，以后用 **Push origin**。Commit保存到电脑，Push才上传GitHub。
7. 在GitHub创建Pull Request，目标选导师指定的整合分支（通常是main；准备分支未合并时听导师安排），由导师查看后合并。

这一步走通“改文件 → 提交 → 推送 → 审阅”。冲突时保留文件，与导师一起解决，不强制推送或删除仓库。

完成标志：导师在GitHub能看到你的准备说明和一次小修改；没有上传真实密钥。

## 以后每次一起开发

| 什么时候 | 做什么 |
|---|---|
| 开始前 | Fetch/Pull，确认分支，约定本次改哪些文件 |
| 开发中 | 小步修改并验证，尽量不同时编辑同一个文件 |
| 完成小步 | 看差异、Commit、Push，需要合并时发PR |
| 结束前 | 记录已完成事项、卡点、下次从哪里继续 |

## 常见问题

| 现象 | 先检查什么 |
|---|---|
| 仓库404 | 网址、当前账户、协作邀请是否接受 |
| 能看但不能Push | 公开可读不等于可写；查协作者权限和Desktop账户 |
| 只有最初的README | Fetch并检查Current branch，准备内容可能在指定分支 |
| 没有package.json | 这是准备阶段；等导师建立应用后按启动说明操作 |
| Supabase无数据 | 查会话、授权和RLS，不直接改成公开可读 |
| AI出现401/402/429或超时 | 和导师查key/权限、余额、频率及网络，避免无限重试 |
| 误提交了真实key | 立即到平台撤销并更换，再告知导师清理Git历史；仅删文件不够 |
