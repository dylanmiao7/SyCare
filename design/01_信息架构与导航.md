# 01 · 信息架构与导航

> 本文件定义 SyCare 前端**有哪些页面、怎么互相到达、为什么这样组织**。
> 上游依据：[20小时开发流程](../docs/01_20小时开发流程.md)、[数据说明](../data/README.md)。

---

## 1. 为谁设计

| 角色 | 是谁 | 设备与场景 | 界面后果 |
|---|---|---|---|
| **主要用户：老人本人** | 66—87 岁，独居或与家人/配偶同住 | 手机上单手操作，多在早上量血压后、晚上睡前；白天光线可能不足 | 字要大、按钮要大、一次只问一件事 |
| 次要用户：家属 | 子女代老人录入 | 偶尔使用 | 记录上必须显示「家属代录」，不冒用本人口吻 |
| 次要用户：社区工作人员 / 朋友 | 支持对象 | 极少使用 | 只在档案里出现，不做独立界面 |

**本期只做老人本人视角**：没有家属端、没有账号切换器、没有多家庭管理界面。代录只在**记录上留标签**，不另开入口。

### 三个必须能跑通的场景

1. **早上记一次血压** — 打开就看到「记健康」，30 秒内填完日期、高压、低压、脉搏并保存。
2. **女儿发来的病历要存起来** — 找到「存病历」，上传 PDF，之后能按日期重新打开。
3. **明天复诊，想带张纸** — 生成小结草稿，看一眼、改几个字、打印。

## 2. 四条设计原则

| # | 原则 | 具体含义 | 反面例子（禁止） |
|---|---|---|---|
| P1 | **大字优先，少即是多** | 正文 ≥ 20px，主按钮 ≥ 64px 高，一屏只讲一件事 | 一屏塞 3 个表单、用 14px 灰字做说明 |
| P2 | **不知道 ≠ 0** | 未记录、设备错误、跳过，三种状态各自有明确文案与样式；缺失一律显示「—」 | 把空血压画成 0，把「跳过」说成「心情不好」 |
| P3 | **说人话，不说术语** | 用「高压 / 低压」，不用「收缩压 / 舒张压」；用「找人聊聊」，不用「干预」 | 用 mmHg、SBP、依从性等词 |
| P4 | **改数据、发消息都要人按** | 上传、保存、生成小结、打印都必须本人点击；问答不自动改记录、不自动通知家属 | 后台静默生成、自动分享给家属 |

## 3. 五个入口（首页即导航）

**不使用底部导航栏。** 老人记不住图标含义，底部 5 个图标会增加误触。首页直接就是 5 个大卡片，每个卡片 = 图标 + 大字标题 + 一句说明 + 右侧箭头。

```
┌──────────────────────────────────────┐
│  SyCare 健康小助手        ⚙ 设置      │  ← 顶栏：只有标题和设置，无汉堡菜单
├──────────────────────────────────────┤
│  模拟老人001 · 84岁 · 与家人同住       │  ← 当前身份条（演示用；正式版是登录名）
│                                      │
│  ┌────────────────────────────────┐  │
│  │ 💬  问一问                      │  │  ← 最高频，放第一位
│  │     健康问题、病历内容都能问     │  │
│  └────────────────────────────────┘  │
│  ┌────────────────────────────────┐  │
│  │ ❤️  记健康                      │  │
│  │     血压、脉搏、睡眠            │  │
│  └────────────────────────────────┘  │
│  ┌────────────────────────────────┐  │
│  │ 😊  记心情                      │  │
│  │     今天怎么样，可以跳过        │  │
│  └────────────────────────────────┘  │
│  ┌────────────────────────────────┐  │
│  │ 📁  存病历                      │  │
│  │     拍照片或存 PDF              │  │
│  └────────────────────────────────┘  │
│  ┌────────────────────────────────┐  │
│  │ 📄  复诊小结                    │  │
│  │     看医生前准备一张纸          │  │
│  └────────────────────────────────┘  │
└──────────────────────────────────────┘
```

| # | 入口 | 文案 | 下方说明 | 对应验收标准 |
|---|---|---|---|---|
| 1 | 问一问 | `问一问` | 健康问题、病历内容都能问 | 能用中文提问，并看到简短回答 |
| 2 | 记健康 | `记健康` | 血压、脉搏、睡眠 | 能新增一条记录，再打开时还在 |
| 3 | 记心情 | `记心情` | 今天怎么样，可以跳过 | 能记录、跳过、回看 |
| 4 | 存病历 | `存病历` | 拍照片或存 PDF | 能上传并重新打开一份模拟病历 |
| 5 | 复诊小结 | `复诊小结` | 看医生前准备一张纸 | 生成一份可编辑的小结草稿 |

> **为什么「问一问」排第一**：README 把「问答入口」列在首位，且它是唯一不需要老人先做记录的功能，新用户第一次打开时能立刻得到反馈。
> **为什么把「记心情」独立出来**：它全部字段可跳过，混在「记健康」里会让老人以为血压也是可跳过的。两个页面各自只讲一件事（P1）。

## 4. 页面清单与路由

原型用 hash 路由；正式版用 React Router，路径保持一致。

| 路由 | 页面 | 入口 | 主要任务 | 优先级 |
|---|---|---|---|---|
| `#/` | 首页 | — | 找到五个功能 | P0 |
| `#/checkin` | 记健康 | 首页② | 新增一条血压/脉搏/睡眠记录 | P0 |
| `#/logs` | 健康记录 | 首页②、首页③ | 回看记录、看变化、发现缺失 | P0 |
| `#/mood` | 记心情 | 首页③ | 记录或跳过心情与交流意愿 | P0 |
| `#/records` | 存病历 | 首页④ | 上传、按日期找回原件 | P0 |
| `#/summary` | 复诊小结 | 首页⑤ | 生成、修改、打印小结 | P1 |
| `#/ask` | 问一问 | 首页① | 提问、看回答与依据 | P1 |
| `#/settings` | 设置 | 顶栏⚙ | 文字大小、身份说明、隐私与数据说明 | P1 |

### 导航规则

1. **返回永远在左上角**，文字是 `← 返回首页`，不是一个裸箭头（老人不一定懂箭头指向）。
2. **不做超过两层的层级**。任何页面从首页出发最多点 1 次到达，返回 1 次回到首页。
3. **保存成功后停留在原页并给出大提示**，不做自动跳转（跳转会让老人以为没保存上）。提示里带一个「看看记录」按钮，想去再点。
4. **表单页离开前**若有未保存内容，弹确认：「刚填的还没保存，确定离开吗？」

## 5. 页面之间的数据流

```
                    ┌──────────────┐
                    │ patients.csv │  档案：姓名、年龄、居住、支持对象、分享偏好
                    └──────┬───────┘
                           │ patient_id
      ┌────────────────────┼────────────────────┐
      ▼                    ▼                    ▼
┌───────────────┐  ┌────────────────┐  ┌──────────────────┐
│daily_checkins │  │medical_records │  │ 上传的 PDF/照片   │
│ 30 天每日记录  │  │  建档 + 随访    │  │   （本会话内存）   │
└───────┬───────┘  └────────┬───────┘  └────────┬─────────┘
        │                   │                   │
        ├───────────────────┴───────────────────┤
        ▼                                       ▼
┌──────────────────┐                  ┌──────────────────┐
│ 复诊小结（草稿）   │                  │ 问一问（只读素材） │
│ 只读事实+人工编辑 │                  │ 带出处、不臆测     │
└──────────────────┘                  └──────────────────┘
```

**关键流向约束**

- 每日记录、病历、上传文件都是**素材**；复诊小结和问答是**只读消费者**，不反向写入。
- 问一问**不能**修改任何记录、**不能**替医生做决定、**不能**自动通知家属。
- 复诊小结由「已有记录」临时生成草稿，标出缺少哪些信息，本人可编辑后再打印。

## 6. 状态设计总览

每个数据页面都必须对下面 6 种情况给出**不同且明确**的界面，这是本项目最核心的设计工作量。

| 状态 | 触发 | 界面表现 | 禁止 |
|---|---|---|---|
| **正常有数据** | 有记录 | 显示数值 + 单位 | — |
| **未记录** `not_recorded` | 当时没量 | 数值位置显示 `—`，徽标「未记录」 | 显示 0、留空白无说明 |
| **设备错误** `device_error` | 血压计坏了/测不出 | `—` + 徽标「设备错误」，附「怎么重新量」说明 | 与「未记录」用同一样式 |
| **跳过** `跳过` | 本人没回答心情 | 显示「这次没回答」，语气中性 | 显示「不太好」、标红 |
| **空列表** | 一条都没有 | 插图 + 「还没有记录，现在就记一条」+ 大按钮 | 空白页 |
| **出错/超时** | 网络或保存失败 | 大字中文提示 + 「重试」按钮 + 数据没丢的说明 | 只转圈、英文报错、静默失败 |

其中「未记录 / 设备错误 / 跳过」三者共用一个**病历语义徽标（ClinicalNotation）**组件，样式与文案见 [02 设计规范 §6](02_设计规范与design-tokens.md) 与 [04 组件契约](04_组件契约与文案库.md)。

## 7. 明确不做的事

| 不做 | 原因 |
|---|---|
| 底部 Tab 导航 / 侧边抽屉 | 老人记不住图标，且增加误触 |
| 家属端、多老人切换、家庭管理 | 本期只做老人本人视角 |
| 把数据存到本地或云端 | 本期仅内存，刷新即重置（页面必须显著提示） |
| 心情趋势曲线、图表堆叠 | 心情字段不是心理量表，画曲线等于过度解读 |
| 自动通知家属 | `wants_to_talk` 只表示意愿 |
| 用药建议、剂量调整、诊断 | 问答不替医生做决定 |
| 深色模式、多语言 | 本期范围外；`preferred_language` 全部为 `zh-CN` |
| 动画、渐变、插画 | 20 小时内优先保证基本操作与正确提示 |
