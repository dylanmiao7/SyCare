# 03 · 逐页规格

> 逐页给出：目的、入口、版式、字段、状态矩阵、交互、文案、验收对照、禁止项。
> 所有示例数值都来自 `data/` 中的真实模拟数据，可直接用于课堂演示。

---

## 全局外壳（App Shell）

所有页面共用的外层结构。

```
┌─────────────────────────────────────────────┐
│ [跳到主要内容]                        ← 键盘可见│
│ ┌─────────────────────────────────────────┐ │
│ │ ← 返回首页       记健康          [字号 A]│ │ ← 顶栏 sticky，高 64px
│ └─────────────────────────────────────────┘ │
│                                             │
│                 页面内容                    │
│                                             │
│ ┌─────────────────────────────────────────┐ │
│ │  模拟演示数据 · 未连接真实后端            │ │ ← 演示横幅，常驻底部
│ └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

| 元素 | 规格 |
|---|---|
| 顶栏 | `position: sticky; top: 0`，高 64px，白底，底部 1px `--c-border-soft` |
| 返回 | 首页无返回；其他页显示 `← 返回首页`，可点区域高 56px |
| 页面标题 | `--fs-h1`(35px) `--fw-bold`，居中或左对齐均可，但**全站统一**（本方案统一左对齐在返回键右侧） |
| 字号按钮 | `A` 按钮，点击弹出「小 / 标准 / 大」三选一，切换 `--fs-root` |
| 演示横幅 | 常驻，`--c-info-bg` 底，20px 字：「模拟演示数据 · 未连接真实后端，刷新后新填的记录会丢失」 |
| 焦点样式 | 全站 `:focus-visible` 3px `--c-primary` + 3px offset |

## P1 · 首页 `#/`

### 目的
让老人在 3 秒内找到他要做的事；同时给出「今天记过了吗」的状态反馈。

### 版式

```
┌───────────────────────────────────────────┐
│  SyCare 健康小助手              [字号 A]   │
├───────────────────────────────────────────┤
│  早上好，模拟老人001                       │  ← --fs-hero 40px
│  84岁 · 与家人同住 · 支持对象：社区工作人员  │  ← --fs-body muted
│                                           │
│  ┌─────────────────────────────────────┐  │
│  │ ✓ 今天还没记                      │  │  ← 今日状态条
│  │   记一条血压，大约 30 秒            │  │
│  └─────────────────────────────────────┘  │
│                                           │
│  ┌─────────────────────────────────────┐  │
│  │  💬   问一问                     ›  │  │  96px
│  │       健康问题、病历内容都能问       │  │
│  ├─────────────────────────────────────┤  │
│  │  ❤️   记健康                     ›  │  │
│  │       血压、脉搏、睡眠              │  │
│  ├─────────────────────────────────────┤  │
│  │  😊   记心情                     ›  │  │
│  │       今天怎么样，可以跳过          │  │
│  ├─────────────────────────────────────┤  │
│  │  📁   存病历                     ›  │  │
│  │       拍照片或存 PDF                │  │
│  ├─────────────────────────────────────┤  │
│  │  📄   复诊小结                   ›  │  │
│  │       看医生前准备一张纸            │  │
│  └─────────────────────────────────────┘  │
└───────────────────────────────────────────┘
```

### 今日状态条（三种状态）

| 条件 | 图标 | 文案 | 底色 |
|---|---|---|---|
| 今天已有血压记录 | `✓` | `今天已经记过了` + `高压 143 低压 79` | `--c-ok-bg` |
| 今天没记录 | `○` | `今天还没记` + `记一条血压，大约 30 秒` | `--c-neutral-bg` |
| 今天记录是设备错误 | `⚠` | `今天的血压没测出来` + `可以再量一次` | `--c-warn-bg` |

- 日期基准：演示数据截止 `2026-08-30`，**「今天」在原型中固定为 `2026-08-30`**（可切换），否则演示时首页永远显示「今天还没记」却没有数据。
- 状态条整条可点击 → `#/checkin`。

### 问候语
按固定演示日期给「早上好 / 下午好 / 晚上好」；**不显示真实当前时间**，避免与 2026-08-30 的数据矛盾。

### 状态矩阵
| 状态 | 表现 |
|---|---|
| 正常 | 如上 |
| 档案加载失败 | 大字段落：「老人的资料没读出来」+「重新读取」大按钮 |
| 空档案 | 「还没有老人资料」+ 说明这是演示版 |

### 禁止项
- ❌ 底部导航栏
- ❌ 任何图表、轮播、广告位
- ❌ 红色的「未完成」提示（不能说老人"漏记"）

## P2 · 记健康 `#/checkin`

### 目的
30 秒内新增一条血压/脉搏/睡眠记录。**这是验收标准里「完成一次记录」的页面。**

### 版式与字段

```
┌───────────────────────────────────────────┐
│ ← 返回首页            记健康               │
├───────────────────────────────────────────┤
│  日期                                      │
│  ┌─────────────────────────────────────┐  │
│  │ 2026-08-30                     📅   │  │ 60px, type=date
│  └─────────────────────────────────────┘  │
│                                            │
│  血压（高压 / 低压）                        │
│  ┌──────────────┐   ┌──────────────┐      │
│  │ 145          │ / │ 76           │      │ 60px each
│  │ 高压 mmHg    │   │ 低压 mmHg    │      │
│  └──────────────┘   └──────────────┘      │
│  [ 高压/低压没测出来 ]  ← 折叠开关          │
│                                            │
│  脉搏                                      │
│  ┌─────────────────────────────────────┐  │
│  │ 77                              次/分│  │
│  └─────────────────────────────────────┘  │
│                                            │
│  睡了几个小时（可以填小数，如 6.5）          │
│  ┌─────────────────────────────────────┐  │
│  │ 7                               小时 │  │
│  └─────────────────────────────────────┘  │
│                                            │
│  记录人：● 老人本人   ○ 家属代录            │  ← 56px, 单选
│                                            │
│  ┌─────────────────────────────────────┐  │
│  │            保 存 记 录               │  │ 64px 主按钮
│  └─────────────────────────────────────┘  │
│  ┌─────────────────────────────────────┐  │
│  │               取消                  │  │ 56px 次按钮
│  └─────────────────────────────────────┘  │
└───────────────────────────────────────────┘
```

### 字段规格

| 字段 | 控件 | 校验 | 错误文案 |
|---|---|---|---|
| `record_date` | `<input type=date>` | 必填；不晚于演示「今天」；不早于 2020-01-01 | 「请选一下日期」「日期不能选以后的」 |
| `systolic_mmhg` | `inputmode=numeric` | 50—300 整数 | 「高压请填 50 到 300 之间的数字」 |
| `diastolic_mmhg` | 同上 | 30—200 整数；**且必须小于高压** | 「低压要比高压小」 |
| `pulse_bpm` | 同上 | 30—220 整数 | 「脉搏请填 30 到 220 之间的数字」 |
| `sleep_hours` | `inputmode=decimal` | 0—24，允许一位小数 | 「睡眠请填 0 到 24 小时」 |
| `recorded_by_type` | 单选 | 默认「老人本人」 | — |
| `capture_status` | 由系统推断 | 见下 | — |

### 空白与设备错误的输入方式

**不做「0 就是没测」的隐式约定。** 两态必须由用户显式表达：

1. 未填任何一项 → 显示确认：「血压和脉搏都空着，这一条只记睡眠吗？」→ 确认后 `capture_status = not_recorded`。
2. 点「高压/低压没测出来」开关 → 展开两选一：
   - `○ 当时没量` → `capture_status = not_recorded`
   - `○ 血压计没测出来` → `capture_status = device_error`

保存后列表里：`not_recorded` → 徽标「未记录」；`device_error` → 徽标「设备错误」。

> **注意**：睡眠为空**不影响** `capture_status`。`capture_status` 只描述血压/脉搏这一组读数（对齐 `data/README.md`：「`systolic_mmhg`、`diastolic_mmhg`、`pulse_bpm` 同时为空时…」）。

### 保存结果

| 结果 | 界面 |
|---|---|
| 成功 | 页面顶部插入成功条（`--c-ok-bg`，48px，`✓ 记好了`）+ 「看看记录」按钮；按钮区变「再记一条」 |
| 校验失败 | 错误文字紧贴该字段下方（`--c-danger-fg`），字段本身边框变红，并把焦点移到第一个错误字段 |
| 保存失败/超时 | 大字提示：「没保存上，可能是网络不好」+「刚才填的内容还在，再试一次」+「重试」按钮 |
| 重复日期 | 「2026-08-30 已经记过了。要改成新的数字吗？」+「覆盖」/「换个日期」 |

### 禁止项
- ❌ 自动把空值当 0
- ❌ 保存成功后自动跳走（老人会以为没成功）
- ❌ 用「请输入」「必须」这类命令式文案；用「请填一下…」
- ❌ 任何医学判断（如「您的血压偏高，建议就医」）

## P3 · 健康记录 `#/logs`

### 目的
回看记录、看出变化、**发现哪些天没数据**。

### 版式

```
┌──────────────────────────────────────────────┐
│ ← 返回首页        健康记录                    │
├──────────────────────────────────────────────┤
│  [ 血压 ]  [ 脉搏 ]  [ 睡眠 ]   ← 分段控件    │
│                                              │
│  近 30 天血压                                 │
│  已记录 28 天 · 未记录 2 天                    │  ← 统计行，必显示
│  ┌────────────────────────────────────────┐  │
│  │ 180 ┤                                  │  │
│  │     │  ░░░░░ 偏高范围 ░░░░░              │  │
```

### 统计行规则
每个分段视图都必须在图表上方显示一句统计，**并且必须同时说清「有几天」和「缺几天」**：

| 视图 | SYN-001 | SYN-003 | SYN-006 |
|---|---|---|---|
| 血压 | `已记录 28 天 · 未记录 2 天`（其中 2 天为设备错误） | `已记录 28 天 · 未记录 2 天` | `已记录 28 天 · 未记录 2 天` |
| 脉搏 | 同上 | 同上 | 同上 |
| 睡眠 | `已记录 27 天 · 未记录 3 天` | `已记录 29 天 · 未记录 1 天` | `已记录 28 天 · 未记录 2 天` |

统计行文案模板：
- 全部有：`近 30 天都记好了`
- 部分有：`已记录 {n} 天 · 未记录 {m} 天`
- 若 `m > 0` 且其中含设备错误：追加 `（{k} 天是设备错误）`

### 图表规格（纯 SVG，无图表库）

| 项目 | 规格 |
|---|---|
| 类型 | 折线 + 数据点，**双线**：高压（主色实心圆点）/ 低压（灰色方点） |
| 尺寸 | 宽 = 容器宽，高 220px（睡眠视图 180px） |
| 参考带 | 高压 ≥140 区域：填充 `--c-chart-band-fill` **+ 1px 描边 `--c-chart-band-stroke`**，右侧直标文字 `偏高范围` |
| Y 轴 | 只标 3 个刻度（100 / 140 / 180），20px 字 |
| X 轴 | 每 5 天一个刻度，显示 `8/1` 形式 |
| 缺失值 | **断开折线**，在缺失位置画 `┄` 虚线段 + 在轴下方对应位置放空心圆；不为缺失点插值、不连线 |
| 设备错误点 | 用 `⚠` 色（`--c-warn-fg`）小标记叠加在缺失位置上 |
| 触摸 | 点击某个数据点 → 该点放大 + 顶部浮出该日详情卡（日期、数值、记录人、状态） |
| 图例 | 必须显示，且用**形状 + 颜色**双重区分 |
| 无障碍 | `<svg role="img">` + `<title>` 概述 + 紧邻的 `<table class="sr-only">` 原始数据表 |

### 每天记录列表
- 倒序；每行显示日期 + 星期 + 记录人徽标 + 各字段值。
- 任一字段缺失 → 显示 `—` + 对应徽标。
- 「未记录」当天**仍然出现在列表里**，不能过滤掉（否则老人不知道自己漏了哪天）。
- 点某行 → 底部弹出该日详情（含 `self_report_note` 原文）。
- 本人记录可「修改」；**家属代录**行显示「家属代录」且不可被本人直接改写（文案：「这条是家人帮忙记的，想改请联系家人」）。

### 状态矩阵
| 状态 | 表现 |
|---|---|
| 有数据 | 如上 |
| 一天都没有 | 插图 + `还没有记录` + `现在就记一条` 大按钮 → `#/checkin` |
| 图表数据全是缺失 | 不画空图表；改显示「这 30 天都没有血压记录」+ 大按钮 |
| 加载失败 | 「记录没读出来」+「重新加载」 |

### 关于 `self_report_note`
数据中有三种留言，处理方式：

| 原文 | 出现 | 界面 |
|---|---|---|
| `今天想按自己的节奏安排生活。` | 316 | 记录列表折叠为「本人留言」，点击展开 |
| `我喜欢安静独处，不希望自动把记录发给家人。` | 30（全属 SYN-006） | **在页面顶部固定显示一条蓝色提示条**（`--c-info-bg`）：「本人设置了不分享，记录不会自动发给家人」 |
| `最近睡得少，想找人聊聊。` | 14（全属 SYN-003） | 在该日记录上显示「本人留言：最近睡得少，想找人聊聊」+ 一个 `找人聊聊` 说明按钮，**该按钮只展开「可以联系谁」，绝不自动发送任何通知** |

### 禁止项
- ❌ 把心情画成折线图（心情不是量表）
- ❌ 缺失点连线或补 0
- ❌ 用红色标「漏记」
- ❌ 「近 7 天趋势下降，注意健康」这类结论性文案

## P4 · 记心情 `#/mood`

### 目的
记录或跳过心情与交流意愿，**错过不产生任何负面反馈**。

### 版式

```
┌───────────────────────────────────────────┐
│ ← 返回首页            记心情               │
├───────────────────────────────────────────┤
│  日期                                      │
│  ┌─────────────────────────────────────┐  │
│  │ 2026-08-30                     📅   │  │
│  └─────────────────────────────────────┘  │
│                                            │
│  今天心情怎么样？                           │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌──────┐│
│  │   😊   │ │   😐   │ │   😟   │ │  ⃠   ││  72px
│  │  很好  │ │  一般  │ │ 不太好 │ │ 不回答││
│  └────────┘ └────────┘ └────────┘ └──────┘│
│                                            │
│  今天想找人聊聊吗？                          │
│  ┌──────────────┐ ┌──────────────┐ ┌─────┐│
│  │    愿意      │ │  暂时不需要   │ │不回答││  72px
│  └──────────────┘ └──────────────┘ └─────┘│
│                                            │
│  想说的话（可以不说）                        │
│  ┌─────────────────────────────────────┐  │
│  │                                     │  │ textarea
│  └─────────────────────────────────────┘  │
│                                            │
│  [        保 存        ]  [    取消    ]   │
└───────────────────────────────────────────┘
```

### 关键规则

1. **「不回答」是合法且等价的选项**，与「很好/一般/不太好」同尺寸同色权重，不使用灰色小字。
2. 两个问题都有「不回答」时，保存按钮文案变为 `就记这些`，仍可保存（记录不完整也是记录）。
3. 保存后文案：`记好了`（中性灰绿，不是庆祝语气）。
4. **跳过不产生任何提示**。禁止：「今天没记录心情哦」这类追责文案。
5. 心情值映射：`很好` → `很好`，`一般` → `一般`，`不太好` → `不太好`，`不回答` → 存储为 `跳过`。
6. **「愿意」不触发任何通知**。保存后若选了「愿意」，只显示一行中性说明：「已记下您想找人聊聊。需要的话可以联系 {support_person}」——`support_person` 从档案读取（SYN-003 显示「朋友」）。

### 与「记健康」的重复日期处理
同一日期可同时有健康记录和心情记录（同一张 `daily_checkins` 表）。心情页保存时：
- 若该日已有记录 → 只更新 `mood_response` / `wants_to_talk` / `self_report_note` 三列，不覆盖血压。
- 提示：「8月30日的心情更新好了。血压记录没变。」

### 禁止项
- ❌ 把「不回答」显示成「不太好」
- ❌ 心情用红绿灯配色
- ❌ 跳过时弹窗挽留
- ❌ 自动通知家属
- ❌ 根据「不太好」给出医学或心理建议

## P5 · 存病历 `#/records`

### 目的
上传病历原件（PDF 或照片），之后按日期找回。**本会话内存存储，刷新即丢——页面必须显著提示。**

### 版式

```
┌──────────────────────────────────────────────┐
│ ← 返回首页           存病历                   │
├──────────────────────────────────────────────┤
│  ┌────────────────────────────────────────┐  │
│  │ ℹ 演示版：上传的文件只保存在这次打开的  │  │ ← 必须常驻
│  │   页面里，刷新后会丢掉。请勿上传真实病历。│  │
│  └────────────────────────────────────────┘  │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │            📁                          │  │
│  │      拍照片或选一份 PDF                 │  │ 大字上传区 160px
│  │      PDF、JPG、PNG，单个不超过 10 MB    │  │
│  │   [   选择文件   ]                      │  │
│  └────────────────────────────────────────┘  │
│                                              │
│  ── 已有病历 (2 份) ──────────────────────    │
│  ┌────────────────────────────────────────┐  │
│  │ 📄 建档记录 · 2026年8月1日              │  │
│  │    来源：中文教学模拟文本   [已确认]     │  │
│  │    [ 查看文字 ] [ 打开原件 ]             │  │
│  ├────────────────────────────────────────┤  │
│  │ 📄 随访记录 · 2026年8月20日             │  │
│  │    来源：中文教学模拟文本   [已确认]     │  │
│  │    [ 查看文字 ] [ 打开原件 ]             │  │
│  └────────────────────────────────────────┘  │
│                                              │
│  ── 我上传的 (1 份) ──────────────────────    │
│  ┌────────────────────────────────────────┐  │
│  │ 📄 SYN-003_模拟病历.pdf · 今天上传       │  │
│  │    [未确认] 图片里的文字还没人核对过     │  │
│  │    [ 打开 ] [ 删除 ]                    │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

### 上传流程（分步，不一次性弹太多）

1. 点「选择文件」→ 原生文件选择器（`accept=".pdf,.jpg,.jpeg,.png"`）。
2. 校验：类型、大小 ≤ 10 MB。
   - 类型不支持 → 「这个文件类型打不开，请选 PDF 或照片」
   - 太大 → 「文件太大了（12 MB），请选 10 MB 以内的」
3. 选好后进入**确认页**：显示文件名、大小、`记录日期`（默认今天，可改，用原生 date）、`这是哪一类`（建档记录 / 随访记录 / 其他）。
4. 点「上传」→ 进度条（百分比数字 20px）。
5. 成功 → 出现在「我上传的」，状态 `未确认`。

### 三种文件状态（对应 `text_status`）

| 状态 | 徽标 | 可否被问答引用 | 说明 |
|---|---|---|---|
| 已确认 | `[已确认]` 绿 | ✅ 可以 | `confirmed_demo`；模拟 CSV 中的病历都是此状态 |
| 未确认 | `[未确认]` 黄 | ❌ 不可以 | 新上传的文件；显示「图片里的文字还没人核对过，暂时不会当成事实回答」 |
| 识别失败 | `[没认出来]` 黄 | ❌ 不可以 | 显示「这份文件里的字没认出来，可以自己填一段说明」 |

> **这是「没有确认过的图片文字，不会被问答当成事实」这条验收标准的界面落点**，必须在页面上显式可见，不能只在后端处理。

### 打开原件
- CSV 中的两条记录无真实 PDF：`打开原件` 显示「这份是教学模拟文本，没有原件文件」+ 展示 `record_text` 全文（可滚动、可选中的大字排版）。
- `data/测试数据/` 中的 3 份 PDF（SYN-001 / SYN-003 / SYN-006）：提供「加载演示 PDF」按钮，选中后以 `<embed>`/`<iframe>` 全屏查看，用 `#page=N` 定位页码。
- 上传的文件：`URL.createObjectURL` 新窗口打开（内存，刷新失效）。

### 状态矩阵
| 状态 | 表现 |
|---|---|
| 无任何病历 | 「还没有存病历」+「把病历拍下来存进去」+ 大按钮 |
| 上传中 | 进度条 + 「正在上传，请稍等」+「取消」 |
| 上传失败 | 「没上传上，文件还在，再试一次」+「重试」 |
| 文件过大/类型错 | 字段级错误提示，不进入上传 |
| 删除确认 | 「确定不要这份了吗？」+「不要了」/「留下」 |

### 禁止项
- ❌ 自动 OCR 后直接当成事实（必须先经人确认）
- ❌ 上传真实病历的引导（演示横幅必须写明「请勿上传真实病历」）
- ❌ 用 `confirm()` 原生弹窗
- ❌ 上传区接受任意文件类型

2. 血压缺失的具体日期
3. 睡眠缺失的具体日期
4. 心情「没有回答」的天数
5. 过敏情况为 `未知` 时（SYN-001、SYN-006、SYN-010、SYN-012）：`过敏情况没有确认过`

## P7 · 问一问 `#/ask`

### 目的
用中文提问，得到**简短、带出处、不知道就说不知道**的回答。

### 版式

```
┌──────────────────────────────────────────────┐
│ ← 返回首页            问一问                  │
├──────────────────────────────────────────────┤
│  ┌────────────────────────────────────────┐  │
│  │ ℹ 演示版：回答由本地规则模拟，未连接    │  │
│  │   DeepSeek。它不会改您的记录。          │  │
│  └────────────────────────────────────────┘  │
│                                              │
│  可以这样问：                                 │
│  [最近血压怎样]  [睡得怎么样]  [病历里写了什么] │ ← 建议问题
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │ 您：最近睡觉怎么样？              14:20 │  │
│  └────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────┐  │
│  │ SyCare：                                │  │
│  │ 近 30 天里有 29 天记了睡眠，平均         │  │
│  │ 6.0 小时，其中 16 天少于 6 小时。        │  │
│  │ 8月26日没有记录。                        │  │
│  │                                        │  │
│  │ 依据：                                  │  │
│  │ • 每日记录 29 条（2026-08-01 至 08-30） │  │
│  │                                        │  │
│  │ ⚠ 这只是根据您的记录整理，不是医生诊断。 │  │
│  └────────────────────────────────────────┘  │
│                                              │
│  ┌───────────────────────────┐  ┌────────┐  │
│  │ 把您想问的写在这里          │  │  问 一 问 │  │
│  └───────────────────────────┘  └────────┘  │
│  [ 清空对话 ]                                │
└──────────────────────────────────────────────┘
```

### 回答的四种类型（必须有不同外观）

| 类型 | 触发 | 回答结构 | 外观 |
|---|---|---|---|
| **能回答** | 问题命中已有记录 | 结论 + 依据列表 + 免责句 | 正常白卡 |
| **不知道** | 记录里没有相关内容 | 「您的资料里没有记这件事。可以在病历里找找，或者下次记一条。」 | 中性灰卡 + `○` |
| **要问医生** | 涉及用药、剂量、诊断（如「药能不能加一片」） | 「这个问题要问医生，我不能替医生做决定。」+「可以在复诊小结里记下来，问医生」+ 按钮跳 `#/summary` | 注意黄卡 + `⚠` |
| **超时/出错** | 请求失败 | 「刚才没答上来，可能是网络不好。」+「再问一次」 | 危险红卡 + 「重试」 |

### 三类必答问题的标准回答模板

**① 「最近血压怎样？」**
```
近 30 天里有 28 天记了血压，平均高压 140、低压 77。
高压最高 148，最低 130，其中 15 天高压到 140 或以上。
8月14日和8月17日血压计没测出来。

依据：每日记录 28 条（2026-08-01 至 2026-08-30）
⚠ 这只是根据您的记录整理，不是医生诊断。
```

**② 「我吃的什么药？」**
```
您的资料里没有记药的名称和剂量，所以我答不上来。
可以在复诊小结的「想问医生的问题」里记下来，下次问医生。

依据：病历记录中提到「药物名称和剂量没有提供」
⚠ 我不会猜药名，也不会建议剂量。
```

**③ 「药能不能加一片？」**
```
这个问题要问医生，我不能替医生做决定。
建议把这个问题记在复诊小结里，看医生时直接问。

依据：本问题涉及用药，超出可回答范围
[ 记到复诊小结 ]   ← 跳 #/summary
```

### 回答规则（写进设计，实现时逐条对照）

1. **必须带日期**：说「近 30 天」或具体日期范围，不能只说「最近」。
2. **必须带天数**：不能只说「平均 140」，要说「28 天里平均 140」。
3. **必须标缺失**：有缺记要主动说，不能只报有数据的部分。
4. **不知道就说不知道**，并说明为什么不知道（资料里没记）。
5. **不做诊断、不建议用药、不推断趋势好坏**。
6. **不给家属发消息、不改记录**。
7. `未确认` 的文件内容**不作依据**；若问题只能靠未确认文件回答，回答「这份文件里的文字还没核对过，我暂时不能拿它回答」。
8. 回答长度上限：正文 ≤ 120 字，依据 ≤ 3 条。

### 状态矩阵
| 状态 | 表现 |
|---|---|
| 初始 | 空对话 + 建议问题 3 个 + 说明 |
| 正在回答 | 「正在看您的记录…」+ 已等待秒数；>8 秒显示「还在算，您可以继续等或者离开」 |
| 能回答 | 见上 |
| 不知道 | 见上 |
| 要问医生 | 见上 |
| 超时/出错 | 见上 |

### 禁止项
- ❌ 无出处的回答
- ❌ 用「您患有…」「说明您…」这类诊断句式
- ❌ 提及 DeepSeek 以外的技术细节
- ❌ 让回答看起来像医生说的话
- ❌ 自动滚动到最新消息（老人会跟丢）——新回答插入后**保持用户当前位置**，并提供「看新回答 ↓」按钮
