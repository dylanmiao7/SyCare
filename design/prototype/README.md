# SyCare 前端原型

这是 [设计文档](../) 的**可点击实现**：老人本人视角、大字界面、真实读取仓库 `data/` 中的模拟数据。
**零依赖、零构建**——只有 HTML、CSS 和原生 ES 模块，不需要 `npm install`。

---

## 一、怎么打开

浏览器的安全策略不允许 `file://` 页面读取 CSV，因此**必须通过本地静态服务打开**。

### 推荐：从仓库根目录启动

```bash
cd SyCare
python3 -m http.server 8777
```

然后访问：

```
http://127.0.0.1:8777/design/prototype/
```

> `python3` 不可用时，也可用 `npx serve`、VS Code 的 Live Server 等任意静态服务器，
> 只要**站点根目录是仓库根目录**（因为原型要读 `/data/*.csv`）。

原型内置了路径自动探测，从 `design/prototype/` 目录启动也能工作。

### 不需要做的事

- ❌ 不需要 `npm install`（没有 `package.json`）
- ❌ 不需要构建（没有打包步骤）
- ❌ 不需要配置 API key（回答由本地规则模拟）

## 二、课堂演示脚本（建议 6 分钟）

| 顺序 | 操作 | 要讲的重点 |
|---|---|---|
| 1 | 打开首页 | 五个入口、96px 大卡片、没有底部导航栏 |
| 2 | 点「换一位演示老人」→ 选 `SYN-001` | 血压趋势；今天已记录 |
| 3 | 「记健康」→ 展开「高压/低压没测出来」→ 选「血压计没测出来」→ 保存 | **未记录 / 设备错误是两种不同状态**，绝不是 0 |
| 4 | 「健康记录」→ 看图表 | 那天是**断线 + 空心圆 + ⚠**，不是 0；上方统计写「已记录 28 天 · 未记录 2 天」 |
| 5 | 点图表上任意一个数据点 | 弹出该日详情：日期、数值、记录人、心情 |
| 6 | 「记心情」→ 心情选「不回答」→ 保存 | 保存后显示「这次没回答」，**不是「不太好」**；没有任何追责提示 |
| 7 | 换到 `SYN-003` | 页面提示「有 20 天的心情是家属填写的」，记录带「家属代录」徽标 |
| 8 | 换到 `SYN-006` | 顶部出现「本人设置了不分享，记录不会自动发给家人」 |
| 9 | 「问一问」→ 点「最近血压怎样」 | 回答带**天数 + 日期范围 + 缺失天数 + 依据 + 免责句** |
| 10 | 「问一问」→ 输入「药能不能加一片」 | 黄卡：「这个问题要问医生，我不能替医生做决定」+ 跳小结按钮 |
| 11 | 「存病历」→ 上传任意 PDF | 上传后状态是**「未确认」**，并说明「暂时不会当成事实回答」 |
| 12 | 「复诊小结」→ 生成草稿 → 打印预览 | 六个章节 + **缺少的信息**清单 + 出处可追溯 + 打印页脚 |
| 13 | 顶栏 `A` → 选「大」 | 全站等比放大，不破版 |

### 演示各页错误状态

在浏览器控制台（F12）里输入：

```js
SyCare.demo.fail.save = true     // 保存失败 → 大中文提示 + 「刚才填的内容还在」+ 重试
SyCare.demo.fail.upload = true   // 上传失败 → 「文件还在，再试一次」
SyCare.demo.fail.ask = true      // 问答超时 → 「刚才没答上来，可能是网络不好」
SyCare.demo.delayMs = 2500       // 把模拟延迟调慢，便于讲解加载态
SyCare.reload()                  // 恢复：重新加载页面
```

| 老人 | 演示什么 | 数据事实 |
|---|---|---|
| `SYN-001` | 血压趋势、本人记录 | 高压平均 140（130—148），15 天 ≥140；2 天设备错误；心情有「跳过」1 天 |

## 四、自动验证

原型带一套自动化测试，用最小 DOM 桩在 Node 里**真实加载全部模块并逐页渲染**，
对关键语义规则做 136 项断言（含端到端流程与回归检查）。

```bash
cd SyCare/design/prototype
node scripts/verify.mjs
```

覆盖：

- 三态缺失值（`recorded` / `not_recorded` / `device_error`）判定与渲染互不相同
- 睡眠与血压状态相互独立
- 「跳过」永远不等于「不太好」
- 本人 / 家属代录标注，以及家属代填主观字段的处理
- 图表在缺失处**断线**、有 `sr-only` 替代数据表
- 四类问答（能回答 / 不知道 / 要问医生 / 出错）与出处、免责句
- 未确认文件不被问答引用
- 覆盖写入不会清掉另一页维护的心情数据
- 复诊小结六章节、缺失清单、无诊断性措辞
- 全站 `data-action` 都有对应动作、所有 class 都存在于 CSS
- HTML 转义（防注入）

> 这套测试在开发中抓出了 4 个真实缺陷，见文末「修复记录」。

## 五、目录结构

```
design/prototype/
├── index.html              入口
├── assets/
│   ├── tokens.css          设计令牌（与 02 文档一致）
│   └── app.css             组件样式 + 打印样式
├── src/
│   ├── main.js             装配：注册视图与动作、启动
│   ├── router.js           hash 路由、渲染、弹层、焦点陷阱
│   ├── state.js            仅内存状态 + 模拟延迟/失败开关
│   ├── data.js             读取 CSV、三态缺失判定、统计、缺失扫描
│   ├── ui.js               基础组件（Button/Field/Alert/Sheet…）
│   ├── domain.js           业务组件（ClinicalBadge/MissingValue/MetricChart）
│   └── screens/            8 个页面
│       ├── home.js  checkin.js  logs.js  mood.js
│       └── records.js  summary.js  ask.js  settings.js
└── scripts/verify.mjs      自动验证（136 项断言）
```

### 代码里的两条硬性约定

1. **`ClinicalBadge` 是唯一徽标实现**，别处不得手写徽标。
2. **`MissingValue` / `bpDisplay()` 是唯一允许渲染「—」的地方**，任何数值展示都必须经过它——
   这样「空值当 0」在结构上就不可能发生。

## 六、本原型的已知边界

| 边界 | 说明 |
|---|---|
| 数据仅存内存 | 刷新即重置。页面底部横幅常驻提示；上传区额外提示「请勿上传真实病历」 |
| 无登录 | 单一老人视角，用首页的「换一位演示老人」做演示；没有权限隔离 |
| 问答是本地规则模拟 | 未连接 DeepSeek。页面已明确标注 |
| 演示「今天」固定为 2026-08-30 | 数据截止该日；否则首页会与数据矛盾（见 [05 §7](../05_数据模型与隐私规则.md)） |
| 图标用 emoji | 避免引入图标库；正式版可换成 SVG 图标集 |
| 需通过静态服务打开 | 浏览器不允许 `file://` 读 CSV |

## 七、修复记录（本原型开发中被测试抓出的缺陷）

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | `dayRow()` 把 `data-action="open-day"` 当作完整属性名拼接，实际输出 `data-action="open-day"="2026-08-30"` | 记录详情弹层**点不开** | 改为 `action` 参数，分别生成 `data-action` 与 `data-open` |
| 2 | 记录人单选按钮带 `data-action="radio"` 但未注册动作 | 全局点击处理 `preventDefault()`，单选按钮**点不动** | 移除该属性，改由原生 `change` 事件绑定 |
| 3 | `badge()` 用数据里的下划线生成类名 `badge--device_error`，CSS 里是 `badge--device-error` | 三态徽标**完全没有样式**，核心视觉约定失效 | 生成类名时把 `_` 换成 `-` |
| 4 | 图表点击热区为 26px 宽矩形，相邻日期互相重叠 | 点某一天却打开**相邻日期**的详情 | 改为以数据点为中心的圆形 / 方圆热区 |
