# 06 · 无障碍、验收对照与范围边界

---

## 1. 无障碍要求（面向老年用户）

老年人常见的视觉与操作障碍：老花、对比敏感度下降、手抖、听不清、短期记忆弱。下面的要求都可测量。

### 1.1 视觉

| 要求 | 标准 | 检查方式 |
|---|---|---|
| 正文 ≥ 20px | `--fs-body` = 1rem = 20px | 浏览器检查任意段落 |
| 支持字号放大到 24px 不破版 | 设置页「大」 | 切换后逐页看一遍 |
| 文本对比度 ≥ 4.5:1 | 见 [02 §2](02_设计规范与design-tokens.md) 实测表 | 全部 ≥ 5.72:1 ✅ |
| 图形/边框对比度 ≥ 3:1 | 图表线、输入框边框 | 最低 4.83:1 ✅ |
| 不仅靠颜色传达信息 | 徽标 = 颜色 + 图标 + 文字 | 灰度截图检查 |
| 不禁用缩放 | 无 `user-scalable=no`、无 `maximum-scale` | 检查 viewport meta |
| 行距 ≥ 1.5 | `--lh-body` = 1.7 | ✅ |
| 段落不两端对齐 | 全部 `text-align: left` | 中文两端对齐会产生大空隙 |
| 无闪烁/自动播放动画 | 无 `autoplay`、无闪烁 | ✅ |

### 1.2 触控

| 要求 | 标准 | 检查方式 |
|---|---|---|
| 点击区 ≥ 48×48px | 全站最小 56px | 见 [02 §4](02_设计规范与design-tokens.md) |
| 主按钮 ≥ 64px | `--tap-primary` | ✅ |
| 元素间距 ≥ 8px | 避免误触相邻 | 分段控件、心情选项 |
| 无仅悬停触发 | 无 `:hover` 独有功能 | 搜索代码无 `mouseenter` 逻辑 |
| 无拖拽 | 全部操作为点击 | ✅ |
| 无手势依赖 | 不需要滑动/长按才能用 | ✅ |

### 1.3 认知

| 要求 | 做法 |
|---|---|
| 一屏一件事 | 记健康、记心情各自独立页面 |
| 不用图标代替文字 | 首页每个入口都有文字标题 + 说明 |
| 不用缩写与专业术语 | 高压/低压，不用 SBP/DBP |
| 错误提示给出下一步 | 「高压请填 50 到 300 之间的数字」，不是「输入无效」 |
| 不自动跳转 | 保存后停留在原页 |
| 不自动滚动 | 问答新回答不抢滚动位置 |
| 不用倒计时 | 无会话超时 |
| 提供返回路径 | 每页左上角 `← 返回首页` |
| 确认破坏性操作 | 覆盖记录、删除文件、清空都有二次确认 |

### 1.4 键盘与屏幕阅读器

| 要求 | 实现 |
|---|---|
| 全部功能键盘可达 | Tab 顺序 = 视觉顺序 |
| 焦点可见 | `:focus-visible` 3px 主色环 |
| 跳到主要内容 | 首个可聚焦元素为 `SkipLink` |
| 语义标签 | `<header>` `<main id="main">` `<nav>` `<button>` |
| 表单标签绑定 | `<label for>`；错误用 `aria-describedby` + `aria-invalid` |
| 动态提示播报 | 成功/错误用 `role="status"` / `role="alert"` |
| 图表替代文本 | `role="img"` + `<title>` + 紧邻 `sr-only` 数据表 |
| 弹层焦点陷阱 | `ConfirmDialog` / `RecordDetailSheet`：焦点锁在层内，Esc 关闭，关闭后回到触发元素 |
| 单选组语义 | `role="radiogroup"` + `aria-checked` + 方向键 |

### 1.5 移动端

| 要求 | 实现 |
|---|---|
| 无横向滚动 | 布局自适应，`min-width: 0` 处理 |
| 支持横屏 | 字号不变，只增加垂直空间 |
| 安全区 | `padding-bottom: env(safe-area-inset-bottom)` |
| 输入法不遮挡 | 输入框聚焦时滚动到可视区 |
| 数字键盘 | 数值字段 `inputmode="numeric"` / `"decimal"` |

### 1.6 打印（复诊小结）

| 要求 | 实现 |
|---|---|
| 隐藏界面元素 | `.appbar` `.demo-banner` `.no-print` 隐藏 |
| 正文 ≥ 12pt | `font-size: 14pt` |
| 保留换行 | `white-space: pre-wrap` |
| 页边距 | `@page { margin: 18mm }` |
| 含免责页脚 | `本小结由已有记录自动整理，不是诊断 —— SyCare 模拟演示` |

## 2. 验收标准对照表

逐条对应 [20小时开发流程 §怎么判断第一版做成了](../docs/01_20小时开发流程.md#L44-L52)。

| # | 验收标准（原文） | 设计落点 | 原型可见 | 状态 |
|---|---|---|---|---|
| 1 | 老人能找到五个入口 | 首页 5 个 96px 大卡片，无底部导航 | 首页 | ✅ 已设计 |
| 2 | 用大字页面完成一次记录 | 记健康页；正文 20px、按钮 64px | 记健康 | ✅ 已设计 |
| 3 | 健康记录能保存和更正 | 保存成功条 + 「再记一条」；重复日期走「覆盖」确认 | 记健康 | ✅ 已设计 |
| 4 | 能看出本人或家属代录 | 每条记录带 `本人记录`/`家属代录` 徽标（`ClinicalBadge`） | 健康记录 | ✅ 已设计 |
| 5 | 缺失读数不会被当成 0 | `bpDisplay()` 唯一入口；`—` + 三态徽标 | 健康记录 | ✅ 已设计 |
| 6 | 病历原件能上传、找回 | 存病历页：上传 → `我上传的` 列表 → 打开 | 存病历 | ✅ 已设计 |
| 7 | 没有确认过的图片文字不被问答当成事实 | `text_status: unconfirmed/unreadable` 徽标 + 问答拒绝引用模板 | 存病历 / 问一问 | ✅ 已设计 |
| 8 | 心情问题可以跳过 | 「不回答」与其余选项同尺寸；存储为 `跳过` | 记心情 | ✅ 已设计 |
| 9 | 「想找人聊聊」只表示意愿，不假装已通知家人 | 「可以联系谁」无发送按钮；无任何通知逻辑 | 记心情 / 健康记录 | ✅ 已设计 |
| 10 | 复诊小结能修改后打印 | 可编辑 textarea + `@media print` 样式 | 复诊小结 | ✅ 已设计 |
| 11 | 小结内容能找到来自哪条记录 | 「这份小结用了哪些记录」+ 每条可点回来源 | 复诊小结 | ✅ 已设计 |
| 12 | 问答只查看本人获授权的资料 | 单一 `patient_id` 作用域；数据源接口按 `patient_id` 取数 | 问一问 | ✅ 已设计 |
| 13 | 问血压应说明日期和已记录天数 | 回答模板强制含「28 天」+ 日期范围 | 问一问 | ✅ 已设计 |
| 14 | 问药能不能加一片，不能替医生做决定 | 「要问医生」黄卡模板 + 跳小结按钮 | 问一问 | ✅ 已设计 |
| 15 | 两个不同家庭账号互相看不到资料 | **本期未实现**（无登录，单老人视角） | — | ⚠ 依赖后端 |
| 16 | 网络或上传失败时页面清楚提示 | 保存失败 / 上传失败 / 加载失败三套大字提示 + 重试 | 全局 | ✅ 已设计 |
| 17 | 老人能看懂、能修改小结 | 白话章节标题 + 直接编辑 | 复诊小结 | ✅ 已设计 |

### 导师技术底线对照

| 底线 | 设计是否覆盖 |
|---|---|
| 服务器核对每个账号能看谁的资料 | ⚠ 需后端；前端已把访问收敛到 `SyCareDataSource`，按 `patient_id` 取数 |
| 病历图片文字经人确认后才能供问答使用 | ✅ `text_status` 驱动，界面显式可见 |
| 问答不自动改记录、不给家属发消息 | ✅ 四类回答模板中均无写操作 |
| DeepSeek 密钥只放后端 | ✅ 前端无任何 key 入口；演示版为本地规则模拟 |

## 3. 范围边界

### 3.1 本期已设计（17 项中的 15 项可上线演示）

首页、记健康、健康记录、记心情、存病历、复诊小结、问一问、设置 —— 共 8 个页面，含全部空/错/缺失状态。

### 3.2 明确不做

| 不做 | 原因 | 何时做 |
|---|---|---|
| 登录、注册、真实账号 | 选了「只做老人本人视角」 | 接入 Supabase 时 |
| 多老人切换、家属端 | 同上 | 第二阶段 |
| 数据持久化（本地/云端） | 选了「仅内存」 | 接 Supabase 时 |
| 真实 DeepSeek 调用 | key 必须在后端 | Edge Function 就绪后 |
| OCR 自动识别病历 | 需人工确认流程 | 第二阶段 |
| 心情趋势图 | 心情不是心理量表 | 不做 |
| 深色模式 | 不在 20 小时范围 | 不做 |
| 多语言 | `preferred_language` 恒为 `zh-CN` | 不做 |
| 提醒/推送/通知 | 违反「不自动通知家属」 | 不做 |
| 用药提醒与剂量建议 | 违反技术底线 | 不做 |
| 动画、插画、渐变 | 优先保证基本操作与正确提示 | 不做 |

### 3.3 已知风险与待确认项

| # | 风险 | 影响 | 建议 |
|---|---|---|---|
| 1 | **`SYN-003` 的心情/交流意愿由家属代填** | 可能把家属意愿当成本人表达 | 需导师确认产品规则，见 [05 §4.3](05_数据模型与隐私规则.md) |
| 2 | 演示「今天」锚定 `2026-08-30` | 与真实日期不符 | 已固定常量；正式版改为真实系统日期 |
| 3 | 「仅内存」下刷新丢数据 | 与验收标准「再打开时还在」冲突 | 演示时**不要刷新**；横幅已常驻提示 |
| 4 | 复诊小结算法与医生习惯不同 | 医生可能不认 | 做成可编辑草稿，本人可改 |
| 5 | 问答为本地规则模拟 | 不是真实大模型 | 页面已明确标注「未连接 DeepSeek」 |
| 6 | 打印排版依赖浏览器 | 不同浏览器差异 | 只用最基础 CSS，避免分页控制 |
| 7 | 中文字体依赖系统 | 无 Web 字体 | 已选系统苹方/雅黑，无需加载 |
